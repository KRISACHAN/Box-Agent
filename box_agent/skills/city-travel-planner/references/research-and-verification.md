# 研究、来源与实时核验

旅行信息变化快。涉及当前开放、交通、票务、天气、价格、活动和规则时，优先检索并链接直接来源。

## 来源优先级

| 等级 | 来源 | 适用信息 |
|---|---|---|
| S | 政府、文旅、交通、气象、海关、使领馆、景区或博物馆官方 | 规则、开放、交通、预警、入境 |
| A | 航空、铁路、公交、酒店、活动主办方和官方预约平台 | 班次、预约、设施、活动 |
| B | 权威媒体、地图服务和成熟旅行平台 | 近期变化、交通估时、区域选择 |
| C | 社区攻略、游记、短视频和评论 | 体验线索、排队、避坑，不作为唯一事实来源 |

## 必须优先核验的字段

- 用户给出明确日期或询问“今天、明天、最近”；
- 景区、博物馆、演出或活动是否开放；
- 门票、预约、最后入场和实名要求；
- 铁路、航班、公交、船班和景区接驳；
- 道路施工、交通管制和节假日服务；
- 台风、暴雨、冰雪、山洪、高温和森林防火；
- 签证、入境、退税和支付规则；
- 户外路线开放、海拔、救援和装备要求。

## 检索流程

1. 先找目的地官方旅游或政务入口；
2. 再找每个强实时项目的直接运营方；
3. 用地图或交通平台核对动线和耗时；
4. 用近期社区内容发现体验问题；
5. 对冲突信息标注日期和来源，优先采用更新且更直接的官方信息；
6. 在最终回复中把来源链接放在对应结论附近。

## 无法核验时

使用保守表达：

- “常见安排是……，但请在出发前通过官方入口复核。”
- “当前无法确认该日期是否开放，先给可替换路线。”
- “交通时间受山路和天气影响，按区间预留，不建议卡点衔接。”

不要使用：

- “一定开放”
- “保证有票”
- “绝对安全”
- “价格就是……”
- “肯定赶得上”

## 事实与建议分离

把输出区分为：

- 已核验事实；
- 基于地理和旅行节奏的规划建议；
- 需要出发前复核的强实时项；
- 用户偏好不足时采用的默认假设。

这样即使实时状态改变，行程主体仍能安全调整。
