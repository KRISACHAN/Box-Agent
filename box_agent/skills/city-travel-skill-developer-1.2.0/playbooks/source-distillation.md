# Playbook：城市旅行资料蒸馏

## 1. 蒸馏目标

把松散资料转成可执行判断规则，避免城市旅行 Skill 变成“资料夹摘要”。

## 2. 资料分层

### 官方事实层

可用于事实判断，但要标注实时核验：

- 交通与口岸；
- 景区/场馆开放；
- 官方票务；
- 官方活动；
- 天气、通关、公共服务。

### 体验判断层

可用于推荐逻辑：

- 哪些点适合第一次去；
- 哪些路线适合亲子；
- 哪些区域适合拍照；
- 哪些安排对体力要求高。

### 社媒表达层

只能用于表达和偏好判断：

- 热门拍照叙事；
- 用户常见吐槽；
- 避坑提醒；
- 小红书式结构。

不得伪造账号、点赞、站内热度或原文。

## 3. 蒸馏字段

每个 POI 或体验建议都建议转为以下字段：

| 字段 | 含义 |
|---|---|
| name | 名称 |
| type | 景点/餐饮/交通/购物/亲子/拍照 |
| audience | 适合人群 |
| duration | 建议停留 |
| energy_cost | 体力成本：低/中/高 |
| queue_risk | 排队风险：低/中/高 |
| weather_dependency | 天气依赖 |
| reservation_needed | 是否可能需要预约 |
| source_level | 官方/用户资料/社媒表达/经验假设 |
| verification_required | 是否需要实时核验 |
| avoid_when | 不建议场景 |
| alternatives | 替代选项 |

## 4. 城市路线建模

路线不是景点列表，而是“入口—区域—节奏—退出点”的组合。

### 入口

- 机场、火车站、口岸、码头、自驾停车、地铁主站；
- 每个入口要标注适合衔接的区域。

### 区域

- 建立 3-6 个核心区域；
- 标注区域之间交通成本；
- 避免一天跨太多远距离区域。

### 节奏

- 上午：低阻力进入；
- 中午：补给与休息；
- 下午：核心体验；
- 晚上：轻量收束或夜景。

### 退出点

- 回到酒店；
- 返回车站/口岸/机场；
- 延伸夜生活或购物。

## 5. 缺资料时的处理

- 可根据通用城市旅行规律给结构；
- 必须标注“待核验”；
- 不要编造具体营业时间、票价、班次；
- 不要把用户上传资料外推为全网结论。

## 6. 输出为知识文件

蒸馏结果应进入：

- `knowledge/city-profile.md`；
- `knowledge/transportation-and-entry.md`；
- `knowledge/audience-scenarios.md`；
- `knowledge/route-branches-and-exceptions.md`；
- `knowledge/real-time-verification.md`。
