# Playbook：SkillHub 发布门禁

## 1. 门禁目标

发布门禁不是为了形式合规，而是避免三个高风险问题：

1. 上传包无法解析；
2. 用户触发后答不稳；
3. 对外文件泄露隐私或包含平台不支持内容。

## 2. 结构门禁

必须通过：

- 根目录存在 `SKILL.md`；
- YAML front matter 存在且可解析；
- `name` 为英文 slug，只含字母、数字、点、下划线、连字符；
- `description` 明确做什么、何时用、典型表达、不该用情况；
- 根目录存在 `README.md` 和 `package.json`；
- `package.json.name` 与 YAML `name` 一致。

## 3. 内容门禁

必须通过：

- 有资料地图或源材料映射；
- 有城市知识索引；
- 有路线分支与异常处理；
- 有实时核验模板；
- 有 3 个完整样例；
- 有 5 条模拟回归；
- 有 TRACE/Depth 评分规则。

## 4. 安全门禁

必须阻断：

- `.DS_Store`；
- `._*` 云同步或 macOS 资源叉；
- 嵌套 ZIP；
- Word、Excel、图片等平台不支持文件；
- 本机绝对路径、用户名、云盘路径；
- API Key、Token、Cookie；
- 历史压缩占位符文本，例如工具历史被省略时留下的方括号英文占位说明。

## 5. 打包原则

- 不在源目录原地删除污染文件；
- 新建干净 staging 目录；
- 只复制允许文件；
- 从 staging 目录生成 ZIP；
- 解包或列清单复核 ZIP 内容。

## 6. 评分建议

| 分数 | 判断 |
|---|---|
| TRACE ≥90 且 Depth ≥90 | 可进入上传前人工预览 |
| TRACE 80-89 或 Depth 80-89 | 可内测，不建议直接上传 |
| 任一低于 80 | 继续补齐内容或结构 |
| 任一低于 70 | 重新设计，不应打包发布 |

## 7. 最终汇报

最终汇报必须说明：

- 是否结构合规完成；
- 是否专业能力完成；
- ZIP 文件名；
- 报告文件名；
- 失败项或人工复核项。
