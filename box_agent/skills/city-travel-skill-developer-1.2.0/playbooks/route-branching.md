# Playbook：路线分支与异常处理

## 1. 为什么必须有路线分支

城市旅行 Skill 的失败常见于两类：一是路线过满，二是遇到异常时只会说“建议自行查询”。路线分支的作用，是在用户信息不完整或现场条件变化时，仍能给出可执行替代方案。

## 2. 标准分支维度

| 维度 | 分支 |
|---|---|
| 时长 | 半日 / 一日 / 两天一晚 / 多日 |
| 节奏 | 轻松 / 标准 / 高密度 |
| 人群 | 亲子 / 老人 / 情侣 / 拍照 / 商务顺路 |
| 预算 | 经济 / 标准 / 舒适 / 奢华 |
| 天气 | 晴天 / 雨天 / 高温 / 台风或极端天气 |
| 入口 | 机场 / 高铁站 / 口岸 / 自驾 / 酒店出发 |
| 核验 | 无实时需求 / 当天必须核验 / 用户要求官方来源 |

## 3. 异常处理样例

### 3.1 用户没说入口

默认策略：

1. 给一个城市中心或酒店出发默认路线；
2. 标注“如果你从机场/车站/口岸出发，我会调整第一站”；
3. 不因缺入口阻塞。

### 3.2 用户只有半天

处理策略：

- 缩到单区域；
- 删除跨城交通或高排队项目；
- 给 1 个核心点 + 1 个餐饮/拍照/休息点；
- 明确不建议硬塞多个远距离景点。

### 3.3 亲子用户

处理策略：

- 降低步行和排队；
- 增加午休和补给；
- 每半天最多 1 个强目的地；
- 标注卫生间、遮阳、室内替代、推车友好等待核验点。

### 3.4 拍照用户

处理策略：

- 按光线、动线、人流安排；
- 允许减少景点数量；
- 明确最佳拍照点需要现场和天气核验；
- 不承诺网红点一定少人。

### 3.5 实时信息缺失

处理策略：

- 不编造营业、票价、班次；
- 给官方核验清单；
- 标注替代方案；
- 如用户要求“今天可用”，必须优先检索或提醒核验。

## 4. 输出格式

每个路线建议都应包含：

```text
适用人群：
默认假设：
主路线：
为什么这样排：
可删减项：
替代方案：
实时核验项：
不建议这样做：
```

## 5. 门禁

如果 Skill 包没有路线分支文件，不能判定为专业能力完成。至少应覆盖 5 类用户场景和 5 类异常处理。
