# SkillHub 展示用 before/after 案例：从泛攻略到城市旅行 Skill 包

> 用途：给 SkillHub 用户、评审人员或团队内使用者快速说明，本技能不是“帮你写一篇城市攻略”，而是把城市旅行经验开发成可复用、可安装、可测试的 AI Skill。

## 1. 展示目标

本案例用于回答普通用户最容易关心的三个问题：

1. **我把一个城市名字丢进去，它到底会变成什么？**
2. **它和普通旅行攻略生成有什么区别？**
3. **为什么文化型城市之外，海岛、购物、美食、徒步城市也值得做成 Skill？**

展示对象采用去品牌化虚构城市「蓝湾市」，它不是文化遗产主导城市，而是典型海岛度假 + 美食 + 轻户外目的地。

## 2. Before：普通泛攻略的样子

用户输入：

```text
帮我做一个蓝湾市旅行助手，适合周末去玩。
```

常见输出会变成：

```text
蓝湾市适合周末游。第一天上午去海滩，中午吃海鲜，下午逛市集，晚上看日落。第二天可以去徒步路线，然后买伴手礼返程。建议带防晒霜、泳衣和舒适鞋子。
```

这类结果的问题不是“没用”，而是**不能复用成 Skill**：

| 问题 | 具体表现 | 对 SkillHub 的影响 |
|---|---|---|
| 场景太泛 | 所有人都走同一条路线 | 无法稳定服务亲子、情侣、银发、徒步等不同人群 |
| 缺少实时核验 | 潮汐、天气、闭园、预约、交通不确定 | 用户到现场才发现不可用 |
| 缺少资料结构 | 只有攻略段落，没有知识库、模板、QA | 不能安装复用，难以维护 |
| 缺少风险边界 | 海况、徒步强度、消费纠纷、退改规则没处理 | 容易产生安全和体验风险 |
| 缺少完成标准 | 不知道做到什么程度才算合格 | 上架评审难判断质量 |

## 3. After：用本技能开发后的城市旅行 Skill 包

同样输入经过本技能处理后，目标不再是一篇攻略，而是一套可安装 Skill 包：

```text
blue-bay-weekend-travel-skill/
├── SKILL.md
├── README.md
├── package.json
├── knowledge/
│   ├── destination-profile.md
│   ├── beach-and-island-rules.md
│   ├── food-and-market-map.md
│   └── outdoor-risk-matrix.md
├── playbooks/
│   ├── weekend-routing-playbook.md
│   ├── non-cultural-city-skill-playbook.md
│   └── real-time-check-playbook.md
├── templates/
│   ├── itinerary-output-template.md
│   ├── route-quick-reference-card-template.md
│   └── non-cultural-city-skill-template.md
├── examples/
│   ├── family-weekend-example.md
│   ├── food-shopping-example.md
│   └── light-hiking-example.md
└── qa/
    ├── quality-gate.md
    └── regression-prompts.md
```

用户安装后可以这样问：

```text
我周六带 6 岁孩子去蓝湾市，想玩沙滩、吃海鲜，但不想太累，预算中等。请给我一个一天半路线，并说明哪些信息要出发前再核验。
```

Skill 应输出：

- 适合亲子的海滩和轻活动，而不是默认热门路线；
- 明确午休、遮阳、雨备和退路；
- 标注潮汐、天气、船班、预约、亲子设施等实时核验项；
- 对海鲜餐厅只给选择标准和候选类型，不编造不可验证排名；
- 给出可复制的一天半路线、备选路线和行前检查清单。

```text

3. 实时核验：天气、潮汐、交通、预约、价格、营业状态
4. 风险边界：海况、强度、儿童安全、消费误导

```

```text

```

### 图 4：文化城市之外也有深度

```text
文化型城市的深度来自历史、博物馆、古建和文明脉络。

```

## 5. 关键 before/after 对照

| 维度 | Before：泛攻略 | After：城市旅行 Skill 包 |
|---|---|---|
| 目标 | 生成一次性路线 | 生成可安装、可复用技能 |
| 结构 | 段落式攻略 | SKILL.md + knowledge + playbooks + templates + examples + qa |
| 非文化深度 | “海滩、美食、购物、徒步”罗列 | 按体验链路、实时条件、风险边界、人群偏好拆解 |
| 可靠性 | 可能编造餐厅、价格、开放状态 | 强制标注实时核验项和不可确认项 |
| 用户体验 | 千人一面 | 亲子、情侣、银发、轻户外、购物美食分流 |
| 上架判断 | 难评估 | 有结构门禁、样例、回归 Prompt 和完成标准 |

## 6. 可直接放入 SkillHub 介绍页的短文案

> 这个技能适合把一个城市开发成可安装的 AI 旅行助手。它不仅支持博物馆、古建、历史文化型城市，也能处理海岛度假、购物、美食、户外徒步等非文化主导目的地。区别在于：它不会只生成一篇旅行攻略，而会把城市知识、实时核验、路线分支、风险边界、输出模板和测试样例整理成一个可复用 Skill 包。

## 7. 展示口径注意事项

- 不承诺实时库存、实时价格、实时营业状态一定准确；只设计核验链路和提醒机制。
- 不把非文化城市写浅；要把深度放在体验链路、约束条件和风险控制上。
- 不使用真实客户、真实项目或可反向识别案例。
- 不把“文化深度型城市”降级；本案例只是补齐非文化主导城市的展示短板。
