# 非文化主导城市样例包：海岛度假型目的地

> 本样例为去标识化示例，用于展示如何把“海岛度假、购物、美食、户外徒步”等非文化主导目的地开发成可复用城市旅行 Skill。示例不代表实时开放、价格或库存信息。

## 1. 样例任务

**用户需求**：开发一个面向普通游客的海岛度假城市 Skill。用户主要关心住哪里、什么时候去、怎么玩、天气不好怎么办，而不是深度历史文化解读。

**目标 Skill 定位**：海岛度假决策助手，帮助用户按人群、季节、预算和体验偏好选择区域、酒店带、路线和降级方案。

**非目标**：
- 不承诺酒店库存、价格和预订成功。
- 不替代当地天气、海况、医疗、救援、签证和法律建议。
- 不把目的地强行包装成文化深度城市。

## 3. 核心模块设计

### 3.1 住宿区域选择器

```markdown
## 住宿区域选择器

先问用户 4 个问题：
1. 更想安静躺平、亲子便利、水上活动、夜生活，还是拍照出片？
2. 是否能接受转船/长车程？
3. 预算是经济、舒适、轻奢还是奢华？
4. 出行月份是否处在雨季或台风季？

输出：
- 推荐 1 个首选区域 + 1 个备选区域。
- 说明适合谁、不适合谁、交通代价、天气风险。
- 标注出行前必须核验的实时信息。
```

### 3.2 天气与海况门禁

```markdown
## 天气与海况门禁

遇到以下情况时，不直接推荐出海或水上活动：
- 官方发布台风、暴雨、强风、海浪预警。
- 用户带老人、儿童或不会游泳者，但计划高风险水上项目。
- 当地海况、船班或活动运营状态无法核验。

改为输出：
- 室内/近距离替代活动。
- 酒店内活动与餐饮方案。
- 改期、退改、保险和安全提醒。
```

### 3.3 三类路线模板

| 路线 | 适合人群 | 路线逻辑 |
|---|---|---|
| 轻松躺平 3 日 | 情侣、银发、疲惫职场人 | 机场接驳 → 酒店休整 → 海滩日落 → 半日轻活动 → SPA/餐厅 |
| 亲子友好 4 日 | 亲子家庭 | 短交通 → 儿童设施 → 浅水海滩 → 室内备选 → 医疗/药店标注 |
| 水上活动 5 日 | 年轻朋友、潜水爱好者 | 海况核验 → 训练/装备 → 浮潜/潜水 → 休整日 → 天气备选 |

## 5. 示例触发语

- “我带两个孩子去这个海岛 4 天，想轻松一点，帮我选住哪里和怎么玩。”
- “我 9 月去，怕下雨，帮我判断哪些活动要提前核验。”
- “预算中等，不想折腾交通，给我一个住区选择和 3 天游玩方案。”
- “如果不能出海，有什么替代路线？”

## 6. 示例输出片段

```markdown
### 首选区域：西海岸亲子酒店带

适合你：带孩子、想少换酒店、希望沙滩近、餐饮方便。这里的优势不是景点多，而是动线短、设施集中、天气不好时也有酒店内替代活动。

不适合你：如果你主要想潜水、夜生活或探索小众海滩，这里会显得太舒适、太商业化。

出行前必须核验：
- 目标月份是否有强降雨或台风风险；
- 酒店儿童设施是否开放；
- 机场接驳是否需要预约；
- 浅水区安全提示和救生员服务时间。

天气降级：
- 暴雨：改为酒店活动 + 室内亲子空间 + 提前订晚餐；
- 风浪大：取消出海，改为海边散步、SPA 或市场餐饮；
- 孩子疲惫：砍掉跨区景点，保留日落和近距离餐厅。
```

## 7. QA 验收

- [ ] 用户能在 30 秒内理解“这个 Skill 帮我选住哪里和怎么玩”。
- [ ] 输出不是景点清单，而是体验决策助手。
- [ ] 至少覆盖天气、交通、住宿、活动、安全、降级 6 个维度。
- [ ] 对实时信息有明确核验提示。
- [ ] 不承诺价格、库存、天气和安全结果。

## 8. 可迁移到其他非文化场景的方式

| 场景 | 替换核心模块 | 保留不变的底层结构 |
|---|---|---|
| 购物城市 | 住宿区域选择器 → 商圈/品牌/退税选择器 | 人群分层、实时核验、降级方案、风险边界 |
| 美食城市 | 活动地图 → 菜系/街区/预约地图 | 体验地图、约束地图、风险地图、替代方案 |
| 徒步城市 | 海况门禁 → 路线难度/天气/装备门禁 | 安全声明、实时核验、撤退方案、QA 回归 |
