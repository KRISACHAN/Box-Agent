# 历史分层知识模型

## 1. 目标

把城市历史转化为旅行助手可调用的知识结构，让路线、推荐和讲解都有清晰主线。

## 2. 历史分层表

| 字段 | 说明 | 必填 |
|---|---|---|
| 历史阶段 | 朝代、时期或文明阶段 | 是 |
| 时间范围 | 尽量给出年份或世纪 | 是 |
| 核心事件 | 对城市形成有影响的事件 | 是 |
| 城市格局影响 | 对城址、街巷、建筑、港口、宗教或商业的影响 | 是 |
| 可见遗存 | 今天还能看到的建筑、遗址、街区或馆藏 | 是 |
| 对应参观点 | 可转化为行程节点的地点 | 是 |
| 理解提示 | 给普通游客的一句话解释 | 是 |
| 易误读点 | 常见误解或过度营销说法 | 否 |
| 核验来源 | 官方或权威来源 | 是 |

## 3. 建模方法

### 3.1 从今天倒推历史

不要写成纯历史教材。每一层都要回答：游客今天在哪里能看见？为什么值得停留？

### 3.2 先主线，后细节

推荐用 3-6 个历史层次建立主线。太细会让旅行助手变重，太粗会失去解释力。

### 3.3 连接路线设计

每个历史阶段都应能连接到至少一个：

- 博物馆展厅
- 古建或遗址
- 历史街区
- 城市空间格局
- 非遗或生活方式

## 4. 输出模板

```markdown
# {城市}历史分层

## 城市文明坐标

{用 200-400 字说明城市在区域史、国家史或世界史中的位置。}

## 历史阶段表

| 时期 | 时间范围 | 核心事件 | 城市格局影响 | 可见遗存 | 对应参观点 | 理解提示 | 核验来源 |
|---|---|---|---|---|---|---|---|

## 初访者理解路径

1. 先从 {入口地点} 理解城市主线。
2. 再通过 {博物馆/街区/古建} 看见历史层次。
3. 最后用 {路线/卡片/FAQ} 帮用户形成记忆。

## 易误读点

- {误读点}：{纠偏说明}
```

## 5. QA 检查

- 是否只是罗列历史名词？如果是，需要改成“历史如何变成今天可看的地点”。
- 是否每个阶段都有可见遗存？没有则不应作为旅行主线。
- 是否混用未核验野史、传说和官方事实？需要分层标注。
