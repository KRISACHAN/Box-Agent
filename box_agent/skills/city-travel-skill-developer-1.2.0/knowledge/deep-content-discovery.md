# 深度内容发现与蒸馏标准

## 1. 定位

本文件用于指导开发者从公开视频、文章、社媒攻略和社区经验中提取可用信息。它不是事实核验替代品，而是发现问题、表达方式和用户关注点的增强层。

## 2. 内容分层

| 类型 | 可用价值 | 是否可直接入库 |
|---|---|---|
| 官方页面 / 公告 | 事实核验、实时字段 | 可入库，需标日期 |
| 博物馆 / 文保机构文章 | 专业知识、展陈说明 | 可入库，需记录来源 |
| 学术或出版社内容 | 历史、考古、建筑依据 | 可入库，需转述 |
| B站 / 长视频讲解 | 观察点、讲解线索 | 需二次核验 |
| 公众号深度文章 | 知识框架、表达方式 | 成功读取原文后可蒸馏 |
| 小红书 / 抖音 / 大众点评 | 体验、避坑、排队、拍照点 | 不能当权威事实 |
| 商业软文 | 可作营销话术参考 | 不作为事实来源 |

## 3. 优先筛选标准

优先选择：

- 有作者身份、机构背景或参考资料的内容。
- 能解释历史背景、工艺、考古过程、建筑细节的内容。
- 视频时长较长且有实地讲解、展厅讲解或专家讲解。
- 评论区能反映真实痛点，如预约难、排队、动线混乱、闭馆误判。

剔除或降权：

- 只有打卡照片，没有解释。
- 标题党、夸张排名、广告植入明显。
- 明显过期的票务、营业时间、交通信息。
- 没有来源的冷知识。

## 4. 提炼输出

对每条可用内容，提炼为：

```markdown
- 来源类型：官方 / 专业机构 / 视频 / 社媒 / 社区
- 是否读到正文：是 / 否
- 可用信息：{事实 / 观察点 / 用户痛点 / 表达方式}
- 核验状态：已核验 / 待核验 / 不采用
- 可进入位置：knowledge / routes / faq / examples / qa
```

## 5. 失败降级

- 如果 URL 读取失败，只能标注为“线索未核验”。
- 搜索结果、标题、摘要不能包装成已读原文。
- 所有实时字段必须回到官方来源或用户授权资料核验。
- 即使增强层全部失败，也不能阻塞基础 Skill 包生成。
