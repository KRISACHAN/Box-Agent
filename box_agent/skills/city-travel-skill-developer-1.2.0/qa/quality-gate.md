# 城市旅行技能开发专家质量门禁

用于发布前人工复核。脚本通过不等于质量通过，必须结合本清单判断。

## 1. SkillHub 结构门禁

- [ ] 根层存在 `SKILL.md`。
- [ ] YAML front matter 可解析。
- [ ] `name` 为英文 slug，只含小写字母、数字和连字符。
- [ ] `description` 写明能力、触发场景、排除场景。
- [ ] `package.json` 与 `SKILL.md` 版本一致。
- [ ] ZIP 内不嵌套 ZIP。
- [ ] 无 `.DS_Store`、日志、临时文件、上传态隐藏文件。

## 2. 城市旅行开发能力门禁

- [ ] 能说明目标城市类型与开发模式：标准型 / 文化深度型。
- [ ] 有资料地图，不把单一攻略当作权威事实来源。
- [ ] 有官方核验字段：开放、票务、交通、活动、通关、天气等。
- [ ] 有社媒表达蒸馏规则，区分事实、体验和表达。
- [ ] 有路线分支：初访、亲子、老人轻松、雨天、预约失败、时间压缩。
- [ ] 有异常降级策略，不因单一来源不可读而停摆。

## 3. 文化旅行深度检查

- [ ] 是否说明城市文明坐标？
- [ ] 是否完成主要历史分层？
- [ ] 重要博物馆是否写明镇馆之宝、重点展厅和看什么细节？
- [ ] 重要古建是否写明年代、形制、保护级别和观察点？
- [ ] 考古发现是否说明发现经过、意义和出土文物现藏地？
- [ ] 是否把历史分层映射到可参观地点，而不是停留在背景介绍？
- [ ] 深度内容推荐是否区分已读取原文、公开线索和未核验内容？
- [ ] 是否避免把社媒打卡内容包装成事实？

## 4. 便携化输出门禁

- [ ] 是否提供城市文明概览卡模板？
- [ ] 是否提供路线速查卡模板？
- [ ] 速查卡是否只保留出发当天真正需要的信息？
- [ ] 是否明确实时核验项，不把模板内容包装成最终事实？

## 5. 隐私与发布风险门禁

- [ ] 对外文件不含本机绝对路径。
- [ ] 对外文件不含用户名、云盘路径、客户真实项目名或合作方名。
- [ ] 示例材料已去品牌化、去项目名。
- [ ] 无密钥、Token、Cookie、账号信息。

## 6. 专业能力完成判定

只有同时满足以下条件，才能说“专业能力完成”：

1. 原有城市旅行 Skill 开发流水线保留；
2. 三阶段增强能力落入实际文件；
3. 标准型与文化深度型双模式可触发；
4. 文化研究、资产建模、便携卡片、质量门禁形成闭环；
5. 校验脚本通过且人工 QA 无 P0 问题。
## 7. 非文化主导场景门禁

用于检查海岛度假、纯购物、美食、户外徒步等目的地是否被正确开发为 Skill，而不是普通攻略。

- [ ] 已识别主导旅行动机，并说明为何不使用文化深度模式作为主线。
- [ ] 已补齐该场景的强实时字段：天气/营业/交通/价格/预约/许可证/安全提示。
- [ ] 已给出路线或场景分支，而不是单一路线。
- [ ] 已明确不适合人群、失败条件、备选方案和降级策略。
- [ ] 已使用 `templates/non-cultural-city-skill-template.md` 或等价结构输出。
- [ ] 若用于 SkillHub 展示，已提供 before/after 或完整样例说明。
