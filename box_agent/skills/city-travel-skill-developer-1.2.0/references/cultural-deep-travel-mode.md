# 文化深度旅行开发模式

本文件用于指导开发者在城市旅行 Skill 中启用“文化深度旅行”增强模式。它来自一次性深度旅行研究能力的抽象，不要求每个城市都强制启用。

## 1. 适用城市

优先适用于：

- 古都型城市：西安、洛阳、南京、开封、北京等。
- 博物馆型城市：拥有国家级、省级重点博物馆和主题馆群的城市。
- 古建密集型城市：大同、太原、泉州、平遥、京都等。
- 世界遗产或考古遗址型城市：敦煌、安阳、良渚、罗马、雅典等。
- 研学旅行城市：用户明确关注历史、建筑、考古、亲子学习和出发前功课。

不建议强制用于：纯海岛度假、商圈美食、城市周末轻松游、网红拍照游。此类城市可只使用内容筛选和路线速查模板。

## 2. 双模式路由

### 标准城市旅行 Skill

目标是帮助用户完成可靠、可执行的城市旅行规划。重点能力包括：

- 官方信息核验；
- 区域与交通建模；
- 场景化路线分支；
- 餐饮、住宿、交通、天气、预约等实时字段提示；
- 异常降级和用户输入缺失处理。

### 文化深度城市旅行 Skill

目标是在标准能力上增加“为什么去、看什么、怎么看”的文化解释力。重点能力包括：

- 城市文明坐标；
- 历史分层；
- 博物馆、古建、考古遗址资产卡；
- 深度内容发现与证据分级；
- 文明概览卡和路线速查卡。

## 3. 开发判断标准

启用文化深度模式前，至少满足以下任一条件：

- 用户明确说“古都、历史、文化、博物馆、古建、考古、研学、深度游、出发前功课”。
- 城市本身的主要旅行价值明显来自历史文化资产。
- 用户提供了博物馆、遗址、历史街区或文化专题资料。
- 目标 Skill 希望差异化于普通攻略助手。

## 4. 输出资产要求

启用后，最终技能包至少补齐：

- `research/city-cultural-dossier.md` 或等价城市文化底稿；
- `knowledge/history-layers.md` 或城市历史分层文件；
- `knowledge/cultural-assets-playbook.md` 或核心文化资产卡标准；
- 便携卡片模板或样例；
- QA 中的文化深度检查项。

## 5. 边界

- 不把社媒打卡内容当作权威事实。
- 不把未读取原文的搜索摘要包装成“已读原文”。
- 不编造镇馆之宝、保护级别、展厅位置、开放时间和预约政策。
- 实时信息必须以官方渠道或用户提供的合法资料为准。
