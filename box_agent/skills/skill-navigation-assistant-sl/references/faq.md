# FAQ 与反模式

## 常见问题

### Q1：为什么你给的中文名称和我理解的不一样？

可能是技能包没有写正式中文名，我只能根据标题、description 或英文目录名推断。此时我会标注可信度；如果你给出正式名称，我会在本轮采用。

### Q2：为什么没有直接帮我安装 SkillHub 技能？

安装技能会改变本地环境，所以必须先获得用户确认。我可以帮你找候选、比较、检查 ZIP 结构和说明安装方式，但不会偷偷安装。

### Q3：为什么复杂任务推荐多个技能？

复杂任务往往不是一个技能能从头做到尾。例如“调研并写成公众号文章”通常需要研究技能先收集资料，再用写作技能成稿，最后用文档/发布相关能力交付。

### Q4：为什么本地明明有技能，你还建议去 SkillHub 搜？

如果本地技能匹配度低、说明不完整，或缺少关键能力，我会保留本地备选，同时建议去 SkillHub 找更合适的技能。

### Q5：健康分低代表技能不能用吗？

不一定。健康分低通常表示说明、元数据或结构不完整，不代表能力一定差。建议先补齐 SKILL.md、description、触发词和边界说明。

### Q6：使用日志没有怎么办？

没有使用日志时，我会按健康分、说明完整度和任务匹配度推荐；有使用记录时再结合高频和最近使用。

## 反模式

- 只输入“推荐一下”，但不说任务目标和交付物。
- 看到一个英文 slug 就要求给官方中文名。
- 让导航技能替代专业技能直接完成合同审查、数据分析、写长文等任务。
- 未确认来源和结构就安装第三方 ZIP。
- 把搜索结果少当作没有技能。
- 工具报错后反复重试同一路径，不检查原因。

## 推荐提问方式

- “我想做一份 XX 报告，已有资料是 XX，最后要 Word/PPT，帮我推荐技能组合。”
- “帮我检查本地技能库，找出缺口，并告诉我去 SkillHub 搜什么。”
- “解释一下 /xxx-skill 适合什么场景，中文名是不是可靠。”
- “这个技能包要上 SkillHub，帮我做结构和 FAQ 补齐。”
