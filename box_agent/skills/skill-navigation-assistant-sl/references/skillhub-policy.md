# SkillHub 补齐、确认安装与启动策略

## 目标

当本地没有足够合适的技能时，技能导航助手不能只回答“没有”。它需要把用户带到下一步：应该去 SkillHub 搜什么、如何筛选、安装前要确认什么、安装后怎么启动验证。

## 触发条件

进入 SkillHub 补齐流程的典型情况：

1. 本地技能匹配度低于 55 分。
2. 前 3 个候选都只能覆盖任务的一小段。
3. 用户明确要求“去 SkillHub 找技能”。
4. 当前技能库缺少某类能力，例如地图、合同审查、PPT、知识库、行业研究。
5. 本地技能说明缺失，无法确认能否胜任。

## 搜索策略

至少给出 2-3 组关键词，避免只搜一个词就下结论。

关键词组合方式：

- 任务名 + 交付物：如“合同审查 风险清单”。
- 能力名 + 场景：如“知识库 网页收藏”。
- 工具名 + 动作：如“飞书 周报 生成”。
- 行业/角色 + 任务：如“酒店旅游 市场调研”。

## 候选筛选标准

优先推荐符合以下条件的技能：

1. 根目录包含 `SKILL.md`。
2. YAML front matter 可解析，且包含 name / description / triggers。
3. description 能说清楚输入、动作和输出。
4. 有 README、FAQ、边界说明或示例。
5. 与用户目标交付物直接相关。
6. 没有要求不明的外部权限或敏感操作。

## 输出模板

```text
本地没有找到高匹配技能。我建议去 SkillHub 搜这些词：

1. {{keyword_1}}
2. {{keyword_2}}
3. {{keyword_3}}

筛选时重点看：
- 是否写清楚输入和输出；
- 是否有 SKILL.md 和触发词；
- 是否有 FAQ/边界说明；
- 是否需要额外账号、Token 或权限。

如果你找到候选链接或 ZIP，可以发给我。我会先检查结构和风险；安装前我会再问你确认，不会偷偷安装。
```

## 安装确认原则

任何会改变本地环境的动作都必须先确认：

- 下载 ZIP。
- 解压到技能目录。
- 覆盖已有技能。
- 修改 SKILL.md 或 package.json。
- 启动外部脚本或第三方依赖。

确认话术：

```text
我已经找到/收到这个候选技能。下一步会把它安装到本地技能目录，这会新增或覆盖文件。
请确认是否继续安装？
```

## 安装后启动检查

安装后不要直接宣称可用，需做最小检查：

1. 根目录是否有 `SKILL.md`。
2. YAML front matter 是否可解析。
3. name 是否与目录/唤起方式一致。
4. description 和 triggers 是否可读。
5. 是否混入 `.DS_Store`、`.gitignore`、云同步隐藏文件、独立 LICENSE 等上传风险文件。

## 失败降级

- SkillHub 搜索不到：换关键词；若仍无结果，输出“未检到”，不要说一定不存在。
- 页面不可读：明确证据缺口，请用户提供正文、截图或 ZIP。
- ZIP 不合格：列出问题和修复方式，不直接安装。
- 用户不确认：停止安装，只保留搜索建议。
