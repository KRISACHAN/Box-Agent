# 中文名称识别与置信度规则

## 目标

解决“中文名称解释有时不准确”的问题。技能导航助手在解释技能名称时，必须优先基于证据，而不是把英文目录名机械翻译成中文。

## 证据优先级

从高到低：

1. `SKILL.md` YAML front matter 中的 `zh_name`、`display_name`、`title`。
2. `SKILL.md` 一级标题中的中文部分。
3. `description`、`triggers`、README 中稳定出现的中文称呼。
4. 目录名 / `name` slug 的英文词根推断。
5. 无证据时保留英文名，并标注“中文名待确认”。

## 置信度

- **高**：来自 `zh_name`、明确中文标题，或 README 中重复出现的正式中文名。
- **中**：来自 description / triggers / 文档正文中的用途短语。
- **低**：只根据 slug 拆词翻译，或名称含缩写、人名、项目代号。

## 输出规则

推荐输出格式：

| 英文名称 | 中文名称 | 可信度 | 依据 | 备注 |
|---|---|---:|---|---|
| skill-navigation-assistant-sl | 技能导航助手 | 高 | YAML zh_name | 可直接使用 |
| hv-analysis | 横纵分析法研究助手 | 中 | description 和触发词 | 中文名为用途解释 |
| abc-x7 | 中文名待确认 | 低 | 仅有 slug | 建议人工确认 |

## 禁止做法

- 不要把 `sl`、`pro`、`x7` 等后缀强行翻译成中文。
- 不要把“用途解释”包装成“官方中文名称”。
- 不要因为中文名不确定就降低对技能用途的分析质量；可以分别输出“名称待确认”和“用途判断”。
- 不要只看文件夹名；至少读取 `SKILL.md` 或说明文件。

## 纠错策略

当用户指出中文名称错误时：

1. 先确认用户提供的新名称是否作为本轮临时名称。
2. 如用户要求修改技能包，再更新 YAML 或 README。
3. 若只是推荐场景，不改原文件，只在本轮输出中采用用户确认名称。
