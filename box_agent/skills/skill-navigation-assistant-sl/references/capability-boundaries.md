# 能力边界、失效场景与降级策略

## 能做什么

- 扫描本地 user / builtin 技能目录。
- 解释技能用途、触发方式、输入输出和边界。
- 根据任务推荐单技能或多技能组合。
- 发现本地能力缺口，并给 SkillHub 搜索与安装确认路径。
- 做技能包健康检查和说明书生成。

## 不能做什么

- 不能在用户未确认时安装、覆盖、删除或执行第三方技能。
- 不能保证 SkillHub 一定存在完全匹配技能。
- 不能在未读取原文、ZIP 或 SKILL.md 时声称已核验。
- 不能替代专业任务技能本身完成深度交付。
- 不能把中文名推断当作官方名称。

## 容易失效的场景

1. 技能包缺少 SKILL.md。
2. YAML front matter 缺失、不可解析或 description 过短。
3. 技能名称是缩写、内部代号、人名或中英文混合缩写。
4. 用户任务过短，例如“帮我弄一下”。
5. 本地技能库没有相关能力，需要外部安装。
6. SkillHub、网页、知识库等外部来源不可读。
7. 用户要求自动安装，但当前流程需要用户确认。

## 降级策略

- 名称不确定：保留英文名 + 用途解释 + 低可信度标记。
- 匹配不足：输出 SkillHub 搜索词，而不是强推弱相关技能。
- 外部不可读：明确证据缺口，只做初步判断。
- 脚本不可运行：回退到读取 SKILL.md 和 README 的人工分析。
- 使用日志缺失：回退到健康分、触发词、description 的排序。
