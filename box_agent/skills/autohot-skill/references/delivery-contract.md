# 交付契约

## 1. 默认交付形式

- 用户未要求文件时，默认在对话中输出结构化 Markdown。
- 用户明确要求“文档、报告、可下载、Word、Excel、PDF”时，才生成对应文件。
- 多文件交付必须打包 ZIP，并在最终回复中提供 ZIP 链接。

## 2. 文件命名

文件名使用英文小写、短横线，不使用空格、中文、随机 UUID。

示例：

- `autohot-daily-brief.md`
- `autohot-sales-morning-brief.docx`
- `autohot-management-weekly-report.xlsx`
- `autohot-skill-optimized.zip`

## 3. 保存路径

- 用户指定目录时，保存到用户指定目录。
- 优化 SkillHub 技能包时，新版必须新建完整目录，不得只生成部分更新文件。
- ZIP 根层必须包含包级 `SKILL.md`，不能只在子目录放入口文件。

## 4. 输出必须包含

每次输出汽车行业情报时，必须标注：

- 数据来源：AutoHOT 线上 API / 缓存 / 公开来源 / 本地验证链路；
- 查询时间；
- 数据时间范围；
- 数据更新时间，如接口可提供；
- 是否为实时线上 AutoHOT 数据；
- 已知限制；
- 关键事实来源链接或事件 ID。

## 5. 场景化输出要求

| 场景 | 默认输出 |
|---|---|
| 每日行业日报 | 摘要、重点事件、品牌/赛道动态、影响判断、来源与限制 |
| 销售晨会简报 | 今日销售关注点、客户沟通话题、竞品动态、建议动作 |
| 管理层周报 | 核心判断、市场变化、品牌动态、风险机会、下周关注 |
| 品牌追踪 | 品牌事件列表、影响判断、趋势信号、销售/运营启示 |
| 事件影响分析 | 事实概述、影响对象、短中长期影响、行动建议、可信度 |

## 6. 验收清单

交付前必须检查：

- 是否覆盖用户指定时间范围；
- 是否明确数据来源与是否实时线上；
- 是否包含来源链接、事件 ID 或可追溯字段；
- 是否区分事实、推断和建议；
- 是否说明接口无数据、配置缺失或缓存限制；
- 是否没有虚构新闻、来源、文件路径或实时性；
- 如果生成文件，文件是否真实存在且可打开；
- 如果打包 ZIP，根目录是否包含 `SKILL.md`。

## 7. 最终汇报模板

```markdown
任务已完成。

- 交付形式：对话输出 / 文件输出
- 数据来源：
- 查询时间：
- 数据时间范围：
- 是否实时线上 AutoHOT 数据：是/否
- 已知限制：
- 下一步建议：
```

## 8. 禁止事项

- 不得声称已生成文件但实际未生成；
- 不得提供不可点击或不存在的文件路径；
- 不得把缓存、本地链路或公开来源冒充为实时线上 AutoHOT；
- 不得省略关键数据限制；
- 不得用无来源结论替代事实依据。
