# 数据质量与引用规则

## 1. 来源分级

| 等级 | 来源类型 | 使用方式 |
|---|---|---|
| A | AutoHOT 线上 API、车企官方公告、监管/协会官方数据 | 可作为核心事实依据 |
| B | 权威媒体、主流财经/汽车媒体、上市公司公告平台 | 可作为事实补充，重要结论建议交叉验证 |
| C | KOL、自媒体、社区讨论、二次转载 | 只能作为线索，不得单独支撑确定性结论 |

## 2. 事实、推断、建议分离

输出必须区分三类内容：

- **事实**：接口返回、官方公告、媒体报道中可追溯的信息；
- **推断**：基于事实做出的趋势、影响、风险判断；
- **建议**：面向销售、运营、管理层的行动建议。

示例：

```markdown
事实：某品牌发布新车型并公布价格区间。
推断：该价格可能对同级燃油车形成竞争压力。
建议：销售团队可准备竞品价格对比话术，但需等待终端优惠政策确认。
```

## 3. 时间规则

- 所有简报必须标注查询时间和数据时间范围。
- 如果接口返回数据更新时间，应原样标注。
- 如果使用缓存，必须标注缓存时间。
- 不得把历史数据写成今天实时数据。

## 4. 冲突信息处理

当来源冲突时：

1. 分列不同说法；
2. 标注来源与发布时间；
3. 优先官方和一手来源；
4. 不下绝对结论；
5. 使用“待确认、尚未核实、存在不一致”表达不确定性。

## 5. 未检到与不存在

- “未检到”只表示当前数据源和条件下没有结果。
- 不得写成“没有发生”“不存在”“品牌无动作”。
- 应给出可操作的扩大检索建议。

## 6. 版权与合规

- 不复刻受版权保护的新闻全文。
- 摘要应转述，不大段复制。
- 投资相关内容只做行业信息整理，不提供买卖建议。
- 法律、监管合规内容只做风险提示，不给最终法律意见。

## 7. 业务判断可追溯

销售晨会和管理层周报中的判断必须能回到事实依据：

- 每个“重点关注”至少对应一条事实或事件；
- 每个“建议动作”应说明适用对象和前提条件；
- 如果证据不足，应降低语气并说明不确定性。
